# Session Commit & PR

ブランチ上に複数の作業が混在する場合でも、**今回のセッションで変更したファイルのみ**を選択してコミットし、プルリクエストを作成します。

## 引数

```text
$ARGUMENTS
```

引数の解釈:

- 引数なし — 全変更を表示し、対話的に対象ファイルを選択
- ファイルパス（スペース区切り） — そのファイルのみをコミット対象とする
- `--all` — 全変更をコミット対象とする（引数として変更なしが確認できる場合のみ使用）

---

## Step 1: 現在の変更を把握する

まず全体の変更状況を確認します:

```bash
git status
```

```bash
git diff --stat HEAD
```

未追跡ファイルも含めて変更ファイルをリストアップし、以下のように分類してください:

- **今回セッションの変更**: 今回の作業で変更・作成したファイル
- **既存の変更（別作業）**: 以前から存在していた変更、または別機能のファイル

`.claude/` ディレクトリ配下は**コミット対象外**です（`.gitignore` に含まれていなくても除外）。

---

## Step 2: コミット対象ファイルの確定

引数でファイルが指定されている場合はそれを使用します。指定がない場合は `AskUserQuestion` で確認します。

**確認ポイント**:

- コミット対象ファイルのリスト
- 現在のブランチ名が変更内容を表しているか（表していなければリネーム提案）

既存ブランチ名が `aaaaaaaaa` や `bagcli` など内容と無関係な名前の場合は、`fix/<内容>` または `feat/<内容>` の命名を提案してください。

---

## Step 3: ブランチ名の確認・変更

現在のブランチ名を確認:

```bash
git branch --show-current
```

### ブランチ運用パターン

状況に応じて以下のいずれかを選択し、`AskUserQuestion` で確認する:

| 状況 | 対応 |
|---|---|
| `develop` / `main` にいる | 新ブランチを作成してから作業（直接コミット禁止） |
| ブランチ名が内容と無関係（`aaaaaaaaa`, `bagcli` 等） | `git branch -m` でリネーム |
| ブランチ名が既に適切 | そのまま使用 |
| 別機能の変更が混在している | 新ブランチを作成し、今回分のみを apply |

**develop/mainにいる場合の新ブランチ作成:**

```bash
git checkout -b <branch-name>
```

> 未ステージの変更はブランチ切り替え時に自動で持ち越される。
> 別機能の変更が混在していても、個別ファイルのみをステージすれば問題ない。

**既存ブランチのリネーム:**

```bash
git branch -m <old-name> <new-name>
```

ブランチ名の規則:

- `fix/<変更内容-kebab-case>` — バグ修正
- `feat/<機能名-kebab-case>` — 新機能
- `refactor/<対象-kebab-case>` — リファクタリング

---

## Step 4: ステージングとコミット

**対象ファイルのみを**ステージングします（`git add .` や `git add -A` は絶対に使わない）:

```bash
git add <file1> <file2> ...
```

コミットメッセージは以下の形式で生成します:

```text
<type>: <変更内容の日本語要約>

## 背景
<なぜこの変更が必要か>

## 変更内容
- <箇条書き>
- <箇条書き>
```

pre-commit フックで自動修正が入った場合は、修正済みファイルを再ステージして再コミットします:

```bash
git add <修正されたファイル>
git commit -m "..."
```

---

## Step 5: プッシュ＆PR作成

```bash
git push -u origin <branch-name>
```

```bash
gh pr create \
  --base develop \
  --title "<type>: <PR タイトル（日本語）>" \
  --body "..."
```

PR 本文テンプレート:

```markdown
## 概要
<1〜3文で変更の目的を説明>

## 背景・根本原因
<なぜこの変更が必要になったか>

## 変更内容
- <箇条書き>

```

---

## 注意事項

- **`git add -A` / `git add .` 禁止**: 無関係な変更を混入させないため、必ず個別ファイルを指定
- **`.claude/` 除外**: このディレクトリはコミットしない
- **pre-commit フック失敗時**: `--no-verify` は使わず、修正後に再コミット
- **ベースブランチ**: 原則 `develop` へのPRを作成
